# 單頁與批次重建的實際經驗

## 單頁資訊圖

原有 TinyPPT 案例以像素座標重建斜切面板、多色標題與編號，將複雜插畫分別裁切。驗收曾發現斜邊遮住標籤、裁切圖的底色擋住前景，以及陰影過強；修正圖層順序、文字所在高度的局部中心線與透明邊緣後，才能交付。

某百分比資訊圖在 LibreOffice 看似正常，PowerPoint 卻把 `28%` 等數字拆行。原因是依賴 Office 的延遲自動適配。現在以建置前量測、固定字級、明確換行與 XML 檢查處理；也不再以大幅自動縮字掩蓋框尺寸錯誤。

## 批次品質容易退步的地方

多張圖如果只共用單頁指令，容易發生漏頁、檔名排序錯誤、上一頁的文字遺留、以同一模板替代不同內容，或把大型含文字插畫裁成一張圖，只編輯主標題。

新版以固定來源清單、每頁文字清單、獨立場景與來源指紋防止錯配。每頁的原生文字／表格／圖片／備註，會在單頁與合併檔之間比對；驗收則綁定目前來源、場景、投影片內容與最終預覽。

這些檢查不能自行發現原圖漏抄的文字。因此，完成清單前仍要逐頁放大檢視所有區塊，合併後也要對照每一頁完整尺寸預覽。物件很多、成功存檔或像素分數很高，都不足以單獨證明已完整轉成可編輯內容。

## 環境與結果分開判斷

Python 版本、缺套件、缺字型或缺 PowerPoint，都屬執行環境問題，不代表來源檔損壞。工具需要明確回報原因；靜態檢查通過也不能標示成已完成 PowerPoint 視覺驗收。
